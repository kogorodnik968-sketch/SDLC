# Глоссарий проекта Siadziba

Глоссарий объясняет термины, которые используются в документах проекта (SRS, SDD, ADR) и на диаграммах UML. Термины расположены по алфавиту. Версия 0.3, 2026-11-22.

| Термин | Определение | Где используется |
|--------|-------------|------------------|
| Автоматическая отмена | Действие системы по расписанию: брони, за которые не внесён залог в течение срока оплаты, переводятся в статус «Отменена», а даты освобождаются | SDD 008, диаграмма состояний |
| Администратор | Сотрудник платформы, который проверяет объявления, блокирует нарушителей и просматривает статистику | SRS 2.4, SDD 005 |
| Актёр (действующее лицо) | Роль, которую играет человек или внешняя система по отношению к системе Siadziba | Диаграмма вариантов использования |
| Блокировка пользователя | Запрет входа в систему, который администратор ставит нарушителю; усадьбы такого владельца скрываются из каталога | SRS REQ-FUNC-019 |
| Бронь | Заявка пользователя на проживание в усадьбе на выбранные даты и её дальнейшая судьба (подтверждение, оплата, отмена); имеет статус | «Подать заявку на бронь», «Оплатить залог», «Отменить бронь» |
| Владелец | Пользователь, который размещает на платформе свои усадьбы, ведёт календарь занятости и принимает заявки | «Управлять усадьбами», «Управлять календарями», «Обработать заявку» |
| Возврат | Часть оплаченной суммы, которая возвращается при отмене брони; зависит от времени до заезда | «Отменить бронь», SDD 009 |
| Двойная бронь | Ситуация, когда на одни и те же даты одной усадьбы оформлены две брони; система такие ситуации не допускает | SDD 008, ADR-004 |
| Диаграмма активности | Диаграмма UML, которая показывает последовательность действий сценария, ветвления и участников (дорожки) | SDD 006 |
| Диаграмма вариантов использования | Диаграмма UML, которая показывает актёров, варианты использования и связи между ними | SDD 012 |
| Диаграмма последовательности | Диаграмма UML, которая показывает, в каком порядке участники обмениваются сообщениями | SDD 011 |
| Диаграмма состояний | Диаграмма UML, которая показывает состояния объекта и переходы между ними под действием событий | SDD 007 |
| Дорожка (swimlane) | Область диаграммы активности, в которой собраны действия одного участника | SDD 006 |
| Заглушка платёжного сервиса | Программная имитация платёжного сервиса, которая используется в учебной версии вместо настоящего провайдера; настоящие деньги не списываются | ADR-003, SDD 005 |
| Залог | Обязательная часть стоимости брони (10 %), которую пользователь всегда вносит онлайн; входит в сумму, которая при отмене не возвращается | «Оплатить залог», SDD 009 |
| Закрытые даты | Периоды, которые владелец вручную отметил как занятые (например, бронь вне сайта) | «Управлять календарями» |
| Календарь занятости | Календарь усадьбы, где свободные и занятые даты показаны по-разному | «Просмотреть карточку», «Управлять календарями» |
| Каталог | Список всех опубликованных усадеб с поиском и фильтрами | «Найти усадьбу» |
| Карточка усадьбы | Страница одной усадьбы: описание, фотографии, цена, удобства, правила, календарь, имя владельца | «Просмотреть карточку» |
| Картографический сервис | Внешний сервис карт; система только формирует ссылку на него с адресом усадьбы | SRS REQ-INT-007 |
| Линия жизни (lifeline) | Вертикальная пунктирная линия на диаграмме последовательности, обозначающая участника взаимодействия во времени | SDD 011 |
| Модерация | Проверка администратором нового или изменённого объявления перед публикацией | SRS REQ-FUNC-018 |
| Обратный вызов (callback) | Запрос, который платёжный сервис сам отправляет в систему, чтобы сообщить результат платежа; подпись запроса проверяется | SDD 005, 011 |
| Отзыв | Оценка (от 1 до 5) и текст, которые пользователь оставляет после завершённого проживания | Планируется по итогам согласования (ЛР4) |
| Платёжный сервис | Внешняя система (в учебной версии заглушка), которая принимает оплату и выполняет возвраты | «Оплатить залог», «Отменить бронь» |
| Пользователь | Актёр диаграммы вариантов использования: любой человек, который работает с сайтом без особых прав (ищет усадьбы, регистрируется, входит, бронирует, оплачивает и отменяет бронь) | SDD 012 |
| Поток событий | Пошаговое описание того, как выполняется вариант использования: основной, альтернативные и ошибочные потоки | Описания прецедентов |
| Постусловие | Состояние системы, которое должно быть достигнуто после завершения варианта использования | Описания прецедентов |
| Почтовый сервис | Внешняя система, через которую платформа отправляет электронные письма участникам | SDD 011, SRS REQ-INT-008 |
| Предусловие | Условие, которое должно быть выполнено до начала варианта использования | Описания прецедентов |
| Прецедент (вариант использования, Use Case) | Последовательность действий системы в ответ на событие, которое запускает актёр; приносит актёру наблюдаемый результат | SDD 012 |
| Рейтинг | Средняя оценка усадьбы по отзывам | Планируется вместе с отзывами |
| Срок оплаты | Время (12 часов), в течение которого необходимо внести залог после подтверждения заявки; иначе бронь отменяется | «Оплатить залог», SDD 008 |
| Статус брони | Состояние брони: «Ожидает подтверждения», «Ожидает оплаты», «Забронирована», «Отклонена», «Отменена», «Завершена» | SDD 007 |
| Статус усадьбы | Состояние объявления: «На проверке», «Опубликована», «Отклонена», «Снята с публикации» | SDD 004 |
| Турист | Роль пользователя после входа в систему, который бронирует усадьбы; на диаграмме вариантов использования это актёр «Пользователь» | SDD 006 |
| Удобство | Особенность усадьбы из справочника (баня, мангал, Wi-Fi и т. п.), по которой можно фильтровать | «Найти усадьбу», «Управлять усадьбами» |
| Уведомление | Электронное письмо участнику о важном событии (новая заявка, решение по заявке, получение оплаты) | SDD 006, SRS REQ-FUNC-021 |
| Усадьба | Загородный дом, коттедж или усадьба, которую сдают в аренду для отдыха | Все документы |
| Время заезда и выезда | Часы, в которые гость может заселиться и должен освободить усадьбу; задаются владельцем; от времени заезда считаются сутки до отмены | SDD 009 |
| ADR | Architecture Decision Record — запись об архитектурном решении и его обосновании | Документация |
| SDD | Software Design Description — описание проектирования ПО | Документация |
| SRS | Software Requirements Specification — спецификация требований к ПО | Документация |
| UML | Unified Modeling Language — унифицированный язык моделирования, графический язык для описания систем | SDD 006, 007, 011, 012; ADR-006 |
